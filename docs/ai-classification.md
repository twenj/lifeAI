# 聊天自动入库规则

聊天成功后，后端对**用户最后一条消息**做分类并尝试写入业务表。日记不走此流程。

## 关键词门禁（必须命中才写入）

| 目标模块 | 文案必须包含 |
|----------|----------------|
| 体重记录 | `体重` |
| 饮食记录 | `饮食` |
| 记事本 | `记事` |
| 日程 | `日程` |
| 待购买 | `购买` |
| 记账 | `收入` 或 `支出` |
| 食物库 | `食物`（且须带图，前端走识图接口） |

没有对应关键词 → **不写入**该模块（即使模型口头说「已记下」）。

## 多关键词优先级

同一句话出现多个关键词时：**越靠前权重越高**，只归入最先出现的那个模块。

| 用户说 | 生效关键词 | 结果 |
|--------|------------|------|
| `支出购买鸡蛋 20元` | `支出` 在前 | 记账 |
| `购买 支出清单本` | `购买` 在前 | 待购买 |
| `记事 日程提醒买菜` | `记事` 在前 | 记事本 |

## 处理策略

1. 先按关键词位置选出主模块，再规则解析；未解析出完整数据再走 LLM
2. 记账必须金额 > 0 才真正写入；可先说「支出 鸡蛋」再补「20元」
3. 置信度够且字段完整才 `applied`；结果写入 `AiExtraction` 审计

## 食物库（前端特殊路径）

- 条件：有图片 + 文案含「食物」
- 调用 `/v1/food-label/recognize`，成功后自动 `createFoodItem`
- 已存在同名食品则跳过重复创建

## 示例

| 用户说 | 结果 |
|--------|------|
| `今日体重70公斤` | 写入体重 |
| `饮食 米饭一碗` | 写入饮食记录 |
| `记事 记得交房租` | 写入记事本 |
| `日程 明天下午三点开会` | 写入日程（需可解析时间） |
| `购买 牛奶 鸡蛋` | 写入待购买 |
| `支出 咖啡 32元` | 写入记账 |
| `每日坚果 食物` + 营养表图 | 写入食物库 |
| `今天70公斤`（无「体重」） | 不入库体重 |
